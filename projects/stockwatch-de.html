StockWatch — eine SwiftUI-Watchlist für iOS

Eine native iOS-Watchlist-App, inspiriert von Scalable Capital. Live-Kurse von Yahoo Finance für über 55 Ticker an sechs Börsen (USA, deutsche Xetra, UK, Schweiz, Dänemark), interaktive Swift Charts mit sieben Zeiträumen, symbol-relevante News, EN/DE-Sprachwechsel zur Laufzeit und Dark-/Light-/System-Theming. Solo entwickelt.

Rolle: Alleinentwickler Stack: Swift · SwiftUI · Swift Charts · async/await Zielplattform: iOS 17+ Quellcode: Öffentlich auf GitHub

Die Aufgabe, die ich mir selbst gestellt habe

Ich öffne Scalable Capital zehnmal am Tag, um auf dieselben fünfzehn Ticker zu schauen. Die App ist gut — nur dass sie mich auf eine Börse beschränkt, für den Chart-Zeitraum extra kassiert und News des Brokers zeigt, nicht des Symbols. Ich wollte mein eigenes Ding.

Die Einschränkungen, die ich mir gesetzt habe: nativ für iOS (kein React Native, kein Hybrid), SwiftUI-first ohne UIKit-Shims, echte Architektur (keine Tutorial-App) und auslieferbar als parallele EN/DE-Erfahrung, weil ein Portfolio-Projekt für den deutschen Markt, das kein Deutsch spricht, ein verpasstes Signal ist.

Architektur

MVVM mit einer Besonderheit: jedes ViewModel ist eine per Swift-Macro generierte @Observable-Klasse, an den @MainActor gepinnt. Das eliminiert die manuelle @Published-Verkabelung, die ältere SwiftUI-Projekte ansammeln, und hält jede UI-Mutation auf dem Main-Actor, ohne DispatchQueue.main.async über die Codebase zu streuen.

Dependency Injection ist protokoll-basiert, nicht container-basiert. Jede Netzwerk-Schnittstelle (Yahoo-Quote-Client, News-Client, Persistenz-Store) ist ein injizierbares Protokoll, sodass die XCTest-Suite Fakes einsetzen kann, ohne den Produktivcode anzufassen. 

// QuoteServicing.swift — the abstraction the ViewModel depends on.
protocol QuoteServicing {
    func latest(for symbols: [String]) async throws -> [Quote]
}

// WatchlistViewModel.swift — main-actor pinned, observable, injected.
@MainActor @Observable
final class WatchlistViewModel {
    private let quotes: QuoteServicing
    var rows: [Quote] = []
    var error: Error?

    init(quotes: QuoteServicing) { self.quotes = quotes }

    func refresh(_ symbols: [String]) async {
        do { rows = try await quotes.latest(for: symbols) }
        catch { error = error }
    }
}
// QuoteClientTests.swift — fake injected, no network in test.
final class WatchlistViewModelTests: XCTestCase {
    @MainActor
    func test_refresh_populatesRows() async {
        let fake = FakeQuoteService(stub: [.fixture(symbol: "AAPL")])
        let vm   = WatchlistViewModel(quotes: fake)
        await vm.refresh(["AAPL"])
        XCTAssertEqual(vm.rows.first?.symbol, "AAPL")
    }
}

Der Sprachwechsel zur Laufzeit

iOS-Apps benötigen normalerweise einen Neustart, um die Sprache zu ändern, weil Bundle.main lokalisierte Strings beim Start gegen die System-Locale auflöst. StockWatch tauscht die Lokalisierung zur Laufzeit aus, indem es Bundle.localizedString(forKey:value:table:) swizzelt, um aus einem nutzer-ausgewählten Bundle (en.lproj oder de.lproj) zu lesen, und dann eine Notification postet, die die Views beobachten.

Warum beide Sprachen

Eine Personal-Finance-App muss sich in jedem Markt, in den sie geht, nativ anfühlen — Tausenderpunkte, Dezimaltrennzeichen, Währungs-Formulierungen und die Labels über Zinszahlen sind alle relevant. EN + DE von Tag eins an mitzudenken war billiger als später nachzurüsten.

Entscheidungen und Trade-offs

Yahoo Finance statt einer kostenpflichtigen API

IEX Cloud, Alpha Vantage und Polygon kamen in Frage. Yahoo's Public-Endpoints sind inoffiziell, aber stabil, kostenlos und brauchen keinen API-Key in einem öffentlichen Repo. Der Trade-off: undokumentierte Rate-Limits — die App debounct Refreshes und cacht aggressiv. Für ein Side-Project ein klarer Gewinn; für Produktion bräuchte es einen Vertrags-Feed.

Swift Charts, nicht SwiftUI Canvas

Swift Charts (iOS 16+) liefert mir die Scrubber-Geste, Achsen-Ticks und Zeitachsen-Formatierung gratis. Selbstgebaut mit Canvas hätte all das nachimplementiert werden müssen. Der Preis: ich bin auf iOS-16+-Minimum festgelegt — das habe ich für @Observable ohnehin auf iOS 17 hochgezogen.

Öffentliches Repo von Tag eins

Keine API-Keys, keine proprietären Daten, keine peinlichen TODOs, die ein Jahr lang drinbleiben. Zwingt mich, README, Lizenz und Basis-Test-Suite zu schreiben, bevor ich vergesse, wie irgendwas funktioniert hat.

Was ich heute anders machen würde

  • Background-Refresh. Heute polled die App nur im Vordergrund. Ein BGAppRefreshTask für stille Background-Updates würde sich nativer anfühlen.
  • Währungs-Normalisierung. Die App zeigt native Währung pro Börse. Ein Nutzer mit Aktien in sechs Märkten braucht eine vergleichbare Zahl, nicht sechs.
  • Apple-Watch-Companion. Die Datenschicht ist genug entkoppelt; die UI wäre ein Wochenende.

Ergebnisse

  • Saubere SwiftUI-App vom leeren Xcode-Projekt bis zum öffentlichen GitHub-Repo, in Feierabend-Stunden über ein Semester verteilt.
  • XCTest-Suite deckt Persistenz-Round-Trips, Refresh-Übergänge und Prozent-Änderungs-Mathematik ab — läuft in unter einer Sekunde im Simulator.
  • Der EN/DE-Sprachwechsel zur Laufzeit ist das meistdiskutierte Detail in Gesprächen über dieses Projekt.
